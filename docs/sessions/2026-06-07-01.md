Arranque del milestone M4 (Stage 10). Se construyó el health board de flota

## Health board de flota

### API — nuevo módulo `modules/health/`

- **`GET /health` (público)**: liveness probe — mongo/redis/uptime, 503 si
  degradado. Hallazgo: SÍ existía un `/health` stub en `webhook.routes.ts`
  (siempre "ok", sin chequear nada — la nota de la sesión anterior de que no
  existía era incorrecta; por eso la sonda de deploy usó 404→401, el stub no
  cambiaba entre versiones). El stub se eliminó: dos registros del mismo path
  habrían tirado el boot con `FST_ERR_DUPLICATED_ROUTE`. Apto para
  healthcheck de Dokploy.
- **`GET /api/v1/admin/fleet-health` (super-admin)**: una sola llamada
  devuelve, por farmacia:
  - **WhatsApp**: conexiones con estado VIVO (consulta a Evolution vía
    `syncConnectionLiveState`, persiste drift + invalida el cache del
    store-resolver — mismo camino que el refresh del dashboard, extraído a
    `connection.service.ts` para DRY).
  - **Catálogo**: conteo real del índice (Meili `/stats`) + `isIndexing` +
    último sync y último error desde `Store.catalog_sync`.
  - **Último mensaje** procesado (timestamp, dirección, sender).
  - **Voz hoy**: total + perdidas (medianoche en el timezone de la farmacia).
  - **Errores recientes**: `last_error` del job de provisioning (se limpia en
    retry/éxito) + error del último sync de catálogo.

### Dashboard — `/admin/health`

Tabla de flota con semáforos: punto verde/ámbar/rojo por conexión WhatsApp,
conteo de productos + "sync hace X", último mensaje con dirección, llamadas
del día con badge de perdidas, columna de errores (OK verde si no hay).
Auto-refresh cada 30s + botón manual. Entrada "Salud de flota" en el
sidebar (sección Administración).

## Deuda de observabilidad pagada (gap de la sesión 2026-06-06)

1. **Éxito silencioso de Meilisearch resuelto**: `upsertDocuments` ahora
   devuelve el `taskUid` y el sync espera el resultado con `waitForTask`
   (las tasks corren en orden de uid → esperar la última cubre todo el
   batch). Task fallida = sync fallido, registrado y visible en el board.
2. **`lastSyncByStore` (in-memory) eliminado**: el cursor de sync incremental
   ahora es `Store.catalog_sync.last_synced_at` (+ `last_error`). Sobrevive
   reinicios — un redeploy ya NO fuerza full rebuild por farmacia — y es la
   fuente del board. El timestamp se captura ANTES de la query a Odoo: el
   solape re-sincroniza algunos productos (upsert idempotente) en vez de
   perder ediciones hechas mid-sync.
3. **`GET /health`** descrito arriba.

## Decisiones de diseño

- El estado WhatsApp del board es **vivo** (N llamadas a Evolution con
  timeout 5s, `Promise.all`, nunca lanza) — a escala actual (pocas farmacias,
  1-3 conexiones c/u) el costo es trivial y el dato es el que importa.
- "Errores recientes" agrega las señales persistidas que ya existen
  (provisioning + sync); no se creó colección de error-log nueva — candidato
  futuro si el board se queda corto.
- `requireSuperAdmin` exportado de `admin.routes.ts` y reutilizado.

## Swagger UI en /docs (mismo bloque, a raíz de una confusión útil)

El usuario buscaba "la página con todos los endpoints" — era de OTRO proyecto
(apiga.onrpa.com/docs). Neo Farmacia solo tenía dos markdown congelados en
abril (~⅓ del API real). Se le dio su propia página viva:

- `@fastify/swagger` + `@fastify/swagger-ui` → **`/docs`** (OpenAPI).
- Cero anotaciones por ruta: un `transform` agrupa por prefijo de URL
  (`TAG_BY_PREFIX` en `app.ts`) y oculta rutas `/dev/`. Los schemas por ruta
  enriquecen los ejemplos gradualmente si algún día se declaran.
- **56 endpoints** visibles agrupados en 14 tags.
- Los markdown viejos (`docs/tech/03-api-reference.md`, `docs/api/README.md`)
  llevan banner apuntando a `/docs`; se conservan por los ejemplos narrativos.

### Hallazgo crítico en el camino: `/health` duplicado

Al inventariar rutas apareció un `GET /health` **stub** preexistente en
`webhook.routes.ts` (siempre "ok", sin chequear nada — la nota de la sesión
2026-06-06 de que "no existía /health" era incorrecta). Dos registros del
mismo path = `FST_ERR_DUPLICATED_ROUTE` → **el API no habría booteado** con
el health board deployado. Stub eliminado; queda solo el probe real.

### Smoke test de boot — `scripts/smoke-boot.ts`

`npx tsx scripts/smoke-boot.ts`: construye la app SIN Mongo/Redis/Odoo
(ioredis lazyConnect), espera `app.ready()` e inyecta `GET /docs/json`.
Atrapa exactamente la clase de error que tsc no ve (rutas duplicadas,
plugins mal registrados) y verifica que ninguna ruta `/dev/` se filtre a
/docs. Correr antes de cada deploy del API.
