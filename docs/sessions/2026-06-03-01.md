# Session 2026-06-03-01: Audit, root-cause fixes, and the voice-calls stack

Covers work from 2026-06-02 → 2026-06-03. Two arcs: (1) a zero-redundancy code audit
that turned into root-causing the long-standing silent-drop bug, and (2) designing and
building the AI voice-calls feature (Stage 9) end to end.

## Arc 1 — Audit + bug fixes

### Code audit (read-only, 3 parallel reviewers)
Full audit of API (~5.2k LOC) + dashboard (~4.6k LOC) for duplication/dead code/efficiency.
Key findings recorded: legacy `odoo.ts` + `modules/odoo` are dead (~280 LOC, deletion
deferred pending live-n8n confirmation), dashboard charts duplicated between home and
reports (~200 LOC, deferred), command dispatch + provisioning runner already lean.

### Fixes shipped
1. **Cross-tenant leak** (`ab0c5c0`) — `chats`/`customers` routes ran only `authenticate`;
   added `resolveStore`. Any logged-in user could read other stores' data before this.
2. **`extractText` hardened** (`ab0c5c0`) — unwraps `ephemeralMessage`/`viewOnce`/`edited`
   envelopes + media captions + button/list replies. Unhandled shapes now log at warn
   with the message keys.
3. **Dashboard api client** (`57bdd9e`) — tolerates 204/empty bodies (DELETE no longer
   false-errors), surfaces the backend's `error` field; disconnect alert shows the real cause.
4. **CORS root cause** (`36453d3`) — "Error al desconectar" was the browser preflight:
   `@fastify/cors` defaults to `methods: GET,HEAD,POST`, silently blocking DELETE (WhatsApp
   disconnect) and PATCH (agent config). Methods now declared explicitly.
5. **THE silent-drop bug — root-caused and fixed** (`72ee0f6`). Live Dokploy logs showed
   `Webhook raw event` → `Webhook received` → nothing. The only unlogged early-return in
   that span was the debounce. `debounce.service.ts` set the Redis key with TTL =
   `windowMs` (2000ms) then slept `windowMs + 100` — **the key always expired mid-wait**,
   the post-sleep GET returned null, every message "looked superseded" and was dropped
   before n8n, regardless of window size. Fix: TTL outlives the wait. Also added: debounce-
   drop debug log, `n8n responded` log (status + response keys), and `output` accepted as
   reply text (n8n AI Agent default field).
6. **`store_leo` fallback removed** (`be0df4f`) — all 8 dashboard pages gated their fetch
   on the resolved store instead of silently querying `store_leo` first (multi-tenant smell
   + console 403 noise).
7. **WhatsApp disconnect** — orphaned Evolution instances (deleted server-side) are now
   cleaned with one click (backend was already tolerant; frontend was the blocker, see #3/#4).

### Open (deliberately untouched)

## Arc 2 — Voice calls (Stage 9)

### Plan
- v1 plan drafted, then **adversarially co-reviewed with Codex CLI** (`codex exec`, 2
  rounds, converged) → v2: customer answers via **one-time signed link** (dashboard is
  only a dev harness), atomic session state machine, chat∈store validation on create,
  compound `{store_id, idempotency_key}` idempotency, voice agent **read-only/
  clarification-only** (no Odoo mutations, refuses clinical advice).
- After evaluating voice quality (OpenAI Realtime voices unconvincing; best voices are
  TTS → pipeline) and reviewing the proven `neo_colmado/WebRtc` LiveKit agent → **v3**:
  LiveKit pipeline (Deepgram STT → LLM → TTS) with all v2 robustness, plus **per-pharmacy
  `voice_config` edited in the super-admin** (with "apply to all") instead of env-hardcoded
  providers. LLM provider is a per-store toggle (openai|anthropic) — Claude is a config
  change, not a rearchitecture. Full plan: `docs/stages/09-voice-calls.md` (v3).
